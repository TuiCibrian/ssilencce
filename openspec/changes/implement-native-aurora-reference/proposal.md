## Why

The collaborator approved a native adaptation of `ssilencce-auroras.html` after restoring the pre-Aurora interface. The selected black-and-white reference must become a coherent Android interface without replacing working music-player capabilities with prototype simulations.

## What Changes

- Add an independently selectable Aurora appearance, enabled only for new installations; retain saved themes and all seven saved player styles.
- Implement the six-destination shell, configurable category tabs/drawer, glass surfaces and lifecycle-aware white ribbon background using Compose with existing Fragment interoperability.
- Adapt home, library/detail screens, mini-player, search, seven players, queue, lyrics, EQ, settings and metadata UI using their actual data and actions.
- Clearly reserve unsupported prototype controls rather than pretending they work.
- Verify build, lint, accessibility, performance and device visuals; document unverified acceptance checks honestly.

## Capabilities

### New Capabilities

- `native-aurora-interface`: Reference-based appearance, navigation, player adaptations and capability-aware states with preference compatibility.

### Modified Capabilities

None. Earlier reverted Aurora proposals remain historical records.

## Impact

UI, appearance preferences, shared theme resources, documentation and a new ADR reconciling ADR-035. No engine, repository, database, network API, dependency, version, signing, contributor or translated-string changes.
