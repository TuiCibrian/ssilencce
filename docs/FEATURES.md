# Feature Inventory

Complete inventory of user-facing features available in the ssilencce app (fork of Booming Music).

Related: `docs/CODE_MAP.md` (per-file code analysis).

## 1. Playback & Audio

- **Media3/ExoPlayer engine** — `PlaybackService` (MediaLibraryService) owns the player, MediaSession, equalizer, notifications, Bluetooth handling and widgets.
- **State persistence** — Queue, position and shuffle order are persisted in Room/SharedPreferences and restored on app start (`PersistentStorage`); queue rows are keyed by position (Room v9), preserving repeated songs. Pending queue edits are retained through pause, and an ordered application-owned writer flushes the final service snapshot without blocking Main. Named queues add snapshots with their own resume position (ADR-041, ADR-045). Switching named queues first awaits the outgoing snapshot (ADR-046); a persistence failure or an unstable departing timeline after bounded retries aborts the switch instead of silently losing the edits. Pending IO cannot be guaranteed after an immediate whole-process kill.
- **Playback modes** — Repeat (off / all / one, plus an optional fourth load-next-and-pause state enabled in Playback settings), three-state shuffle (off / shuffle / randomize) with a configurable button cycle, play on startup (never / last position / first song), clear queue on completion. Randomize selects a random next song on every transition instead of materializing a shuffled order; it persists across restarts and has no fixed play order, so the queue screen keeps showing timeline order while randomize is active. The shuffle button cycles only through the states enabled in Settings > Playback > Shuffle mode (standard shuffle and randomize switches); if both are disabled the cycle keeps standard shuffle reachable. Standard shuffle can be configured to shuffle all songs of the queue or only the songs below the current one. The player-level load-next-and-pause state is persisted separately from Media3 repeat mode; each automatically loaded item starts paused at 0 and the queue wraps to its first item paused at the end. Per-song menus, queue item menus and the Now Playing menu expose Pause after this song, Play after current song (moves an existing copy instead of duplicating it) and Load next song and pause.
- **A-B repeat** — The player menu cycles Set A → Set B → Clear for the current track; playback loops A→B until cleared and any song change clears the loop. A small chip over the player cover shows the A / A-B markers and clears the loop on tap. The playback service schedules one wake-up at B (no position polling) and accounts for playback speed.
- **Per-track resume** — Optional opt-in remembers the last position of long-form tracks (10 minutes or more), resumes them later and clears the position on completion. Positions are written through the ordered non-blocking `TrackPositionWriter`; seek-generation guards prevent stale bookmark seeks after manual seeks (ADR-042).
- **Session recovery** — Optional opt-in resumes the saved queue and position after Android recreates the playback service; it does not claim to survive force-stop (ADR-042).
- **Fade-in/fade-out** — Optional 0–4000 ms volume ramps on play and pause (0 = off). A single `PlaybackVolumeController` composes the equalizer volume, audio-focus ducking and the fade multiplier, and the sleep-timer fade-out uses the same ramp. Pause is applied only when the fade-out completes; play/pause commands cancel an in-progress ramp.
- **Gapless playback toggle** — On by default; when off, `GaplessGateAudioSink` strips the encoder delay/padding (including offload delay/padding) so the untrimmed audio is played.
- **Crossfade** — Optional 0–12 s equal-power overlap between tracks (default off). A secondary ExoPlayer pre-buffers the next queue item, both players run complementary volume ramps, and the main player commits the queue transition before the outgoing track ends; the media session, queue, persistence, widgets, notifications and scrobbling keep using the single main player. Optional crossfade on manual skip (capped at 4 s). Automatically skipped between consecutive tracks of the same album while gapless playback is enabled (configurable). Suppressed for repeat-one, A-B repeat, stop-after-current-song, sleep-timer stop-at-end, repeat-load-next-and-pause and while a Chromecast receiver owns playback.
- **External-audio mini player** — Opening a `content:`/`file:` audio file from another app shows a Compose dialog-style player with play/pause, seek, close and **Open in app**. It plays in a local ExoPlayer so the main queue is not replaced; main playback is paused while it is open and restored on close unless Open in app hands the song to the main queue.
- **Song preview** — The song menu **Preview** action plays a song in the same popup without adding it to any queue. Main playback is paused and restored afterwards; preview playback is not counted in history or play statistics.
- **Resume policies** — **Only resume if paused by disconnect** prevents resume-on-connect after a manual pause. **Prevent unwanted autoplay** ignores play commands sent automatically by Bluetooth/car stacks for 5 seconds after a connection; its **Strict mode** ignores external play commands whenever the app is in the background.
- **Mute handling** — Pause on zero volume resumes at the first non-zero step, and **Don't start playback when muted** defers play requests until the media volume rises.
- **Quick Settings tile** — Playback tile mirrors playing/paused/unavailable state from the live session and toggles play/pause with a lifecycle-bounded controller (ADR-042).
- **Smart shuffle modes** (`ShuffleManager`) — Pure random, most played, favorites, forgotten songs, recently added, combined, by-group shuffle; album/artist plus album-artist/composer most-played strategies; album-artist works on all supported versions, while composer (Android 11/API 30+ only, matching the Composers category) is hidden below API 30; per-open shuffle behavior (on/off/remember). Special-shuffle replacement rebuilds the weighted queue and starts playback at the first item (position 0); it does not preserve the previous current item, position or play/pause intent. Non-special/native shuffle behavior is unchanged.
- **Queue behavior** — Configurable tap-on-song action (play single song / play whole list / play next / queue at end) and queue-clearing behavior (remove all vs. keep current).
- **Shuffle actions** — Long-press multi-select in song, album, artist, year, folder and search lists offers Shuffle play plus a Shuffle and then… submenu with Shuffle and play next and Shuffle and add to queue; the selected songs are randomized before being played, queued next or appended. The queue overflow action Reshuffle queue remains available only for the fixed shuffle order and reports that randomize has no order to rebuild.
- **Controls** — Previous-button behavior (restart the current song after 5 s or always play previous; applies to UI, notification and headset), independent fast-forward and rewind durations (5–60 s, legacy seek interval migrated), fast-forward/rewind only for long audio (off / 10 / 20 / 30 / 60 minutes; short-track headset seek falls back to next/previous), mini-player swipe-to-skip, extra controls, adaptive/circle/animated buttons.
- **Headset button mapping** — Playback → Headphones opens a Compose dialog for single, double, triple and long-press actions from a transport-only set (Play/Pause, Next, Previous, Seek forward, Seek backward, Nothing), an optional 4+ Seek forward action, and a 250–600 ms delay. Defaults preserve single Play/Pause, double Next, triple Previous, long Play/Pause, 4+ off and 300 ms. Dedicated Next/Previous/FF/Rewind keys remain with Media3. Long press and mapping depend on the headset/Android/AVRCP stack; the dialog documents the limitation.
- **Audio processing** (`renderer` + `processor`) — Per-channel balance, ReplayGain (album/track mode, preamp, peak limiting on 16/24-bit PCM) and a stereo/mono downmix processor (`MonoAudioProcessor`) injected into `DefaultAudioSink`; mono can be toggled at runtime without reconfiguring the sink; ALAC hardware-decoder workaround for broken high-bitrate M4A.
- **Per-song speed and pitch** — An optional per-song override persisted in Room (`SongPlaybackParamEntity`, DB v9) is applied on every media item transition and falls back to the global tempo when no row exists. The speed and pitch section of the sound settings sheet offers "Apply to this song only" and "Reset song", and shows the stored per-song values.
- **Software decoding fallback** — Jellyfin FFmpeg decoder (`media3-ffmpeg-decoder`) auto-loaded by the Media3 extension renderer for codecs MediaCodec cannot handle (e.g. ALAC). Custom Media3 extractors add AIFF/AIFC and DSF/DFF playback: AIFF is converted to the sink's little-endian PCM encodings, DSF/DFF 1-bit DSD is decimated to 88.2 kHz PCM16 (DST-compressed DSDIFF is rejected). APE and WMA remain unplayable: the packaged FFmpeg build enables only flac/alac/pcm_mulaw/pcm_alaw/mp3/aac/ac3/eac3/dca/mlp/truehd (no ape/wmav1/wmav2/wmapro), and the song info screen reports that limitation.
- **Audio device integration** (`AudioOutputObserver`) — Resume on headphone/Bluetooth connect, pause on disconnect, resume-only-if-paused-by-disconnect, unwanted-autoplay guard (standard and strict), pause at zero volume with resume at any non-zero step, don't-start-when-muted, system media output switcher (incl. MIUI/Samsung OEM intents), Xiaomi Mi Play detection and bit-perfect state.
- **Audio focus** — Four modes: Normal, Ignore focus, Ask before taking focus (with confirmation when another app is audible) and Resume after call. Ask uses a restorable Compose dialog tied to the live request; repeated play preserves it, while explicit/no-op pause, cancel, mode change/abandon/release invalidate it. Stale confirmations cannot start playback. Transient loss and ducking remain owned by `AudioFocusController`; there is no automatic timeout (ADR-042, ADR-045).
- **Advanced** — MP3 index seeking, stop when closed from recents, play option always visible / whole list, play all songs when searching.

## 2. Equalizer & Sound

- **Equalizer** with three engine choices: the classic `android.media.audiofx.Equalizer` (device-fixed bands, shown read-only), `DynamicsProcessing` (API 28+, multiband compressor/limiter) with selectable 3/5/10/15/31 ISO band layouts, and a **System equalizer** hand-off that disables the in-app engine and drives the OEM panel through the effect-control session broadcasts. Changing the band count interpolates the current curve in log-frequency space instead of resetting it, legacy 32-band data migrates to 31, and AutoEq imports map their point cloud onto the selected band count.
- **Effects** — Bass boost, virtualizer, loudness, compressor, limiter.
- **Mono output** — Mixes 16-bit stereo PCM to a single signal on both channels; takes effect on the next buffer and is bypassed by multichannel/float output.
- **Reverb (experimental)** — An `EnvironmentalReverb` attached to the playback audio session with Small room / Medium room / Large room / Medium hall / Large hall / Plate presets and custom room level, room HF level, decay time, decay HF ratio, reflections level/delay, reverb level/delay, diffusion and density controls. It is created on demand, disabled for bit-perfect/audio-offload, and released when the audio session changes or the playback service stops.
- **Balance, tempo (speed/pitch), system volume** controls.
- **EQ profiles** - Named profiles with broad output-type associations and optional exact per-device keys (hashed Bluetooth/USB identity where the OS exposes it); exact device wins over type, unassociated outputs keep the current profile. Profile saver/editor exposes “Use with this device” when an identity is available. Import/export (JSON and AutoEq TXT format), persistence in DataStore. Saved profiles keep their own band count; selecting a profile with a different count switches the engine to it, while changing the count resamples the applied curve. **Cast / remote** MediaRouter routes (TV, cast speaker, AVR and speaker groups) are available as a profile association type, including an exact hashed route key.
- **ReplayGain** - Album/track/off modes with preamp, reading standard, iTunes `----:com.apple.iTunes:` and Opus R128 tags with Standard > iTunes > R128 alias priority; malformed/blank gains and peaks are treated as missing. A **Calculate ReplayGain** action in the song-selection, album and artist menus measures audio with EBU R128/BS.1770 (400 ms blocks, 100 ms hop, gating), writes format-aware tags, verifies them by reading back, and writes album gain only when the complete album is selected. A measured 0.00 dB tag remains present and uses the with-tag preamp. A complete-album write failure suppresses and rolls back new album gain/peak for the whole album; remaining tracks may still receive track tags. Cancellation preserves completed/failed counts, and playback peak limiting applies to any finite positive peak, including tags above 1.0. The writer reopens the file to verify persisted tags, writes WAV through an explicit RIFF `ID3 ` chunk codec (preserving `fmt `/`data` and non-RG tags) with a staged app-private persistent backup/restore under `noBackupFilesDir/replaygain-wav-backup` on failure, and M4A as `----:com.apple.iTunes:REPLAYGAIN_*` freeform atoms, and fails closed only if the container still cannot persist the values; corrupt or materially truncated decodes (including AAC encoder-delay-aware duration checks) fail per file, and the result lists each failed title/reason. WAV recovery copies are app-private, survive process death/reboot, and are excluded from cloud/device-transfer backups; recovery is per-song on the next write, with no global startup scan, so stale backups for songs never rewritten can persist. Legacy cacheDir backups are not migrated or swept. The current AA-06 codec/writer checkpoint is not yet independently accepted; final review, frozen build and device WAV/M4A gates remain pending. The ReplayGain card also exposes **Use embedded tags** (off: every song uses the without-tag preamp), **Prevent clipping** (peak limiting, default on), a **Headroom** slider (0–12 dB attenuation before limiting) and **Constant volume** (one constant gain for every song instead of per-track tag gains; default off). All four keep the previous behavior as their default.
- **Sound settings sheet** — Volume, per-channel balance, tempo and mono output controls reachable from the player, plus per-song "Apply to this song only" / "Reset song" actions; audio offload, float output and skip-silence controls; ReplayGain mode/preamp, reverb and the calculation action live in the Equalizer screen.

## 3. Lyrics

- **Synced and plain lyrics** — LRC/enhanced-LRC and TTML (Apple Music) parsing with translations, transliterations and actor assignment (duets M/F).
- **Sources** — Embedded tags, lyrics files (`.lrc`/`.ttml`), embedded via LRC files, and online providers: **Lyrically** (iTunes-based, Jaro-Winkler scoring), **BetterLyrics**, **LRCLib** (close-duration search); cached in Room (`LyricsEntity`).
- **Lyric line selection** - On the full lyrics screen, the select-lines action enters selection mode; tap lines to toggle them (long-press also toggles in this mode), Select all, then Copy to the clipboard or Share as `text/plain` through the system chooser. Plain lyrics can also start selection with a long-press. Selection is reset when the song or resolved lyrics change. Copied text contains the main line text only (translations/transliterations are not included).
- **Per-song lyrics source** - A tune action on the full lyrics screen opens a source picker: Automatic (existing file → embedded → downloaded priority), Embedded only, Downloaded only, or any `.lrc`/`.ttml` document picked through SAF. The choice is stored per song id in `filesDir/lyrics/lyrics_sources.json` (no Room schema change); picked documents keep a persisted read permission, and an unreadable document falls back to automatic resolution.
- **Manual lyric synchronization** - The lyrics editor has Edit and Sync modes. Sync mode lists the plain lyric lines, plays the current song, assigns the playback position to the target line on **Stamp**, enforces increasing timestamps, and adjusts each stamped line by ±100 ms. Stamped lines can be saved as embedded synced lyrics (existing metadata writer) or exported as an `.lrc` file next to the audio file (direct write when possible, SAF `CreateDocument` otherwise; a SAF export becomes the song's chosen lyrics file). TTML sources are not offered as stampable plain text.
- **A-B repeat from lyrics** — Long-pressing a synced lyric line opens Repeat this line / Set A here / Set B here / Clear A-B repeat; "Set A here" then "Set B here" on a later line defines an arbitrary range, and the range is shown by the player A-B chip.
- **Syllable mode & karaoke** — Word-by-word highlighting (`SpannedWordText`), karaoke-style text fill, progressive coloring, blur/shadow text effects, animated backgrounds.
- **Lyrics display** — Full-screen lyrics view and lyrics over the cover, auto-scroll, active line centering, horizontal centering, RTL support, custom font import, line spacing, font sizes and bold per mode (synced/plain × player/fullscreen).
- **Lyrics editor** - Edit text with preview across Embedded/Downloaded/File sources, instrumental detection, online search, save to lyrics/LRC files, and an Edit/Sync mode switch for manual lyric timing (Stamp, ±100 ms, embedded or `.lrc` output).
- **Instrumental detection** — By title keywords (configurable identifiers) or short exact lyrics.
- **Advanced** — Ignore blank lines, preferred file format (TTML/LRC), force UTF-8, resume-on-seek, line-crossfade settings.

## 4. Library & Organization

- **Media collections** — Songs, albums, artists, separate album artists and composers, genres, release years, folders (filesystem explorer with SAF), playlists.
- **Folder management** — The Folders tab keeps the linear/hierarchical toggle (also in Settings > Library > Folders). Folder actions include a **Folder info** dialog (path, direct and total song counts, sub-folders, total duration, total size, created and last-modified dates), **Create folder**, **Rename folder**, **Exclude folder** (confirmation, writes the existing blacklist) and **Hide from library** for songs (writes the blacklist; reversible in Settings > Library > Blacklist). Creating and renaming write directly when the destination is writable and otherwise through persisted SAF trees; a MediaStore rescan follows every filesystem change. Song/file menus and multi-select add **Move to folder** and **Copy to folder**: files are streamed to a writable folder or a SAF `DocumentFile`, names are uniquified, and moves delete the source through SAF, a direct file delete or MediaStore. Android 10 uses the recoverable delete intent; Android 11+ asks for confirmation with `MediaStore.createDeleteRequest`, and declining the request keeps the copies. Missing source files are skipped and reported.
- **Ghost mode** — User-chosen ghost folders are excluded by path prefix from the shared song query, so songs, albums, artists, genres, years, folders, playlists, favorites, history, play counts, search, shuffle sources, widget now-playing metadata and Android Auto browsing all ignore them. The filter lives in `GhostMode` + `RealSongRepository.makeSongCursor`; Room-backed playlist/stat queries reapply it when mapping stored entities. Folder menus and **Advanced > Privacy > Ghost mode** add/remove ghost folders; the master switch is off by default. No Room or permission change.
- **First-run setup wizard** — A Compose `SetupWizardActivity` is shown once after the permission screen on a new installation (upgrades never see it automatically). It offers a welcome step, a folder step that edits the existing whitelist/blacklist tables and the `start_directory` main music folder with a Compose storage browser, a scanning step with the optional auto-rescan switch, and a finish step with a library rescan. Skip leaves the folder lists untouched. It is re-openable from Settings > Library > Setup wizard.
- **Library rescan** — Rescan library asks `MediaScannerConnection` to refresh the chosen folders (the whitelist when non-empty, otherwise the mounted storage roots, always including the main music folder). It is available from the wizard and from Settings > Library, serializes concurrent scans and has a 120 s completion guard. When the optional auto-rescan switch is on, a process-scoped, 2.5 s-debounced `ACTION_MEDIA_MOUNTED` receiver schedules the same rescan; it is permission-guarded and off by default.
- **Composer and album-artist tabs** — Album artists reuses the existing album-artist queries and detail/playback flow. Composers uses `MediaStore.MediaColumns.COMPOSER` on Android 11+ (the category is hidden below API 30; no metadata scan) and reuses the artist detail/playback screens. When both Artists and Album artists are visible, Artists lists regular artists and hides the legacy “Only album artists” toggle; when Album artists is hidden, the previous behavior is unchanged.
- **Album-artist fallback** — Default-off "Use album artist when artist is missing" preference: songs whose artist tag is empty or unknown resolve to the album artist for list/player/notification display, global search and artist grouping; fallback artist groups open the album-artist detail and remain playable from Android Auto.
- **Album composer filter** — On Android 11+ the album list offers Filter by composer when album songs contain composer tags. A Compose choice dialog lists All composers plus normalized composer names and filters the existing album grid; the action is hidden below API 30 and when no composer data exists. The selection is restored after recreation.
- **Genre subcategories** — Genre detail offers View with Songs, Albums and Artists. Albums and artists reuse the existing album/artist adapters and detail screens and are derived from the same genre song query. Sort menus, Play, Shuffle and quick search follow the visible subcategory, while the header keeps the full genre song count and duration; the selected subcategory is restored after recreation.
- **Multi-disc albums** — Album detail groups songs by disc and shows a "Disc N" section header when the album spans more than one disc and the list is sorted by Track. Songs without a disc tag are treated as disc 1.
- **Home screen** — Greeting header, last added, top tracks, history, shuffle button and suggestions.
- **Content types** — Favorites, history (configurable cutoff interval, individual and multi-select removal), last added (configurable interval), not-recently-played, top tracks, top albums/artists, never played.
- **Not Recently Played threshold** — The smart list defaults to the history interval and offers a Compose dialog to set an arbitrary 1–3650-day window or return to the history interval. The choice is persisted in existing preferences, applies to the Home suggestion and updates the list and subtitle after saving.
- **Play counts** — Per-song play/skip counters and time played (incremented at 50 % of duration), top-100 flows.
- **Non-destructive statistics reads** — Play-count and history reads filter missing/deleted files without deleting rows; explicit `Repository.deleteSong`/`deleteSongs`, `clearPlayCount`, `clearSongHistory` and the **Remove missing songs** maintenance action (Settings > Advanced) remain the only cleanup paths. The 100-row `PLAY_STATS_LIMIT`/`HISTORY_LIMIT` is still applied before the missing-file filter, so sparse windows can show fewer than 100 and omit valid rows beyond the window. The maintenance action deletes playlist entries, play counts, play events and history rows for songs whose files no longer exist; the startup `deleteMissingContent()` cleanup (playlists only) is unchanged.
- **Library maintenance** — Settings > Advanced > Maintenance > **Remove missing songs** scans MediaStore for songs whose files no longer exist, reports the count, and after confirmation removes their playlist entries, play counts, play events and history rows in one pass. It never deletes files or MediaStore rows.
- **Play statistics periods** — Top Tracks and Top Artists support this week, this month, last 12 months, this year and all time. Period artist attribution uses recorded event names; later metadata changes do not rewrite it. Artist percentages use all plays in the selected period, not just the displayed top 100, and denominator-only changes remain reactive. Snapshot-only artists remain visible with unavailable media actions disabled. All time retains earlier aggregate counts and artist-ID identity (ADR-040). The options menu exports the current period's top 100 Top Tracks or Top Artists as UTF-8 CSV through SAF, with RFC 4180 escaping and formula-injection neutralization; no storage permission is required. An optional automatic export can write the latest completed local calendar week, month or year to a persisted SAF folder through a daily WorkManager check: up to two top-100 CSVs use the same writer and auto names, each file is staged as `.partial` and renamed only after the complete write, only the latest completed period is caught up after missed runs, NoData creates no files, handled failures retry the pending period on the next daily check, and older files are never deleted.
- **Sorting** — Locale-aware numeric collator (natural number order), article-ignoring sort (The/A/El…) with a user-editable keyword list, per-entity sort keys with persistence, and filename, path, track-number, date-modified, date-last-played, most-played and least-played keys on the all-songs, folder-song, genre-song and year-song lists. Play-statistics keys join the cached play-count table in memory (5 s TTL).
- **List display** — Song rows can follow the sort order (File name key shows the file name), always show the song title, or always show the file name. An optional, default-off switch appends a localized date-only modification label to the existing secondary text. Global-search song results use the same title mode and suffix. Compact album/artist rows and Home suggestions have no secondary text view and remain unchanged. Both controls live in Appearance > Display and apply on the next list bind or reload.
- **Views** — List/grid modes, 5 grid view types (normal, card, colored card, circle, image), configurable grid size, larger header image, fast scroller.
- **Library filtering** - Whitelist/blacklist folders (`InclExclDao`), minimum and maximum song duration (maximum 0 = unlimited; library queries only), minimum songs per artist/album. Duration bounds are library-browsing only: queue resolution, ID/path/file-provider resolution, delete cleanup, saved playlists and favorites are not duration-filtered. Genre detail lists, genre search, genre song counts and the unknown-genre list use the same duration bounds as the other library lists. The setup wizard writes the same whitelist/blacklist tables and force-enables the corresponding switches when it saves a non-empty list.
- **Covers** — Embedded/folder art (cover.jpg etc.), MediaStore art, ignore-MediaStore-covers option, use-folder-art option, online artist images and album covers (Deezer), preferred image size.
- **File operations** — Batch delete with MediaStore trash requests (recoverable) and SAF fallback, delete to trash option.
- **Supplementary extra-format indexing** — Opt-in "Index extra audio formats" library setting (default off). Scans the whitelist folders (or MediaStore song folders plus the public Music folder) for `.aif/.aiff/.aifc/.dsf/.dff` files MediaStore does not index, reads tags/duration with TagLib (header fallback for DSD/AIFF), applies the library duration range and blacklist, and caches results in `filesDir/extra_formats/library.json`. Cached songs appear in song lists/search, play from `file://` URIs, and survive queue/favorite/history round trips through stable negative ids. The cache is refreshed on a manual rescan, when the switch is toggled, or after six hours at startup. APE/WMA are excluded while the bundled FFmpeg cannot decode them.

## 5. Playlists

- **CRUD** — Create, rename, edit (name, description, custom cover via Photo Picker), delete playlists; favorites playlist.
- **Playlist management** — Drag & drop reordering, internal search, song counts, multi-select.
- **Import/export** — Import device playlists (M3U and others), export as `.m3u`, `.m3u8` or `.pls` (MediaStore on Android 10+). Device import uses only the checked songs (deduplicated by ID); no exact name collision imports directly. An exact collision opens a Compose dialog with Keep both (default, first free suffix 1..100), Replace existing (single exact non-Favorites target only, transactional contents replacement preserving playlist ID/name/description/cover) and Rename imported (validated new name, existing playlist untouched). Cancel never mutates. Creates and replacements run in Room transactions and name resolution is serialized; success reports the actual stored name. Single and batch export share a format chooser. Directory writes stage beside the target. On Q+, exports use `MediaStore.Files` with the format's concrete playlist MIME (not the legacy `Audio.Playlists` name-rewriting path); the writer stages and publishes complete content before a checked rename replaces the same-name target. Pre-commit failure preserves old bytes and attempts to restore its name. A provider refusing rollback can leave old bytes under a backup name; failed post-commit cleanup can leave an extra backup. The format chooser is a Compose dialog that survives recreation; selecting an export dismisses the dialog and hands the request to a process-owned executor, so rotation does not cancel it and a restored token cannot start it twice. Public MediaStore APIs provide no atomic-swap or power-loss guarantee (ADR-044).
- **Add-to-playlist** — Compose bottom sheet with search and multi-select.

## 6. Search

- **Global search** — Text field, voice input, 300 ms debounce, grouped results (albums, artists, songs, playlists, genres), and the last 20 submitted queries shown as removable chips (plus Clear history) while the query field is empty.
- **Search filters** — Smart, basic and last-added filters; scoped searches within genre, playlist, year and folder.
- **Ghost search** — A separate search screen lists and plays only songs inside ghost folders. Open it by long-pressing the search field, from **Advanced > Privacy > Ghost mode**, from the optional `Ghost search` media-notification button, or from the lock-screen player when ghost mode is enabled. An optional 4–12 digit PIN gates the screen; with no PIN configured it opens directly. The screen explains when ghost mode is off or no folder is configured.
- **Settings search** — A search action in Settings indexes every preference section, groups matches by section and opens the selected section (scrolling to the key when present).
- **Quick list search** - A bottom search field on the songs, albums, artists, playlists, genres, years and folders lists filters the loaded list in place and restores it when cleared. The query is fragment-owned, saved across configuration recreation and replayed against the list so the visible text and rows remain aligned. The same bar is available on the generic detail/statistics list and on the song sections of album, artist, genre, year, folder and playlist detail; album/artist filtering is songs-only, folder matching includes the file name, and playlist filtering is drag-safe (filtered rows are never persisted and the full order is saved on pause).
- **System integration** — Android searchable config, search action, hold-tab-to-search.

## 7. Now Playing Screen

- **7 player styles** — Default, FullCover, Gradient, Plain, Material 3, Expressive, Peek — retained View/controls fragments outside Aurora; Compose Aurora chrome reuses their shared cover pager and actions without adding a style. The Aurora square cover sits centered in its stage (360 dp, 280 dp compact) with a smooth pre-blurred cached bitmap halo (bounded cache, single draw per frame, no per-frame blur), and FullCover keeps its glass controls over the reference backdrop.
- **Gestures** — Configurable single-tap (including `Open fullscreen art`), double-tap (left/right/center), long-press on cover; swipe on cover, swipe anywhere, swipe-up for queue, swipe-down to dismiss.
- **Keep screen on** — Optional default-off switch keeps the display awake while the expanded Now Playing panel is visible; cover lyrics continue to keep the screen awake independently, and dialogs do not.
- **Fullscreen artwork** — A Compose viewer opens from the cover tap action (`Open fullscreen art`) or the player overflow menu, with pinch-to-zoom, save to the gallery (`MediaStore.Images`), and set-as-wallpaper for home, lock screen or both (requires the normal `SET_WALLPAPER` permission; pre-Android 10 gallery writes use the storage permission already requested at startup).
- **Share Now Playing** — The player overflow menu renders the full player view to a JPEG and opens the share sheet, with an optional centered 1:1 crop for social apps; the temporary file is exposed through the existing FileProvider authority.
- **Seek helpers** — Tapping the elapsed-time label or the overflow `Seek to...` item opens a Compose dialog that accepts `mm:ss` (or `h:mm:ss`) input and clamps to the track duration. A separate default-off `Touch only on thumb` preference makes both the legacy `MusicSlider` and the Compose Aurora slider ignore track taps so only dragging the thumb seeks.
- **Quick-access row** — Optional user-selected shortcuts (lyrics, equalizer, sleep timer, tempo, queue, tag editor, add to playlist) render as a row in Now Playing. The default is empty (no visual change). Settings offer a checklist with up/down reordering; the Aurora screen places the row in its controls column and legacy styles use a Compose overlay at the top of the player.
- **Page transitions** — Carousel effect plus 10 PageTransformers (depth, 3D flips, hinge, cascading, parallax, vertical stack, zoom-out…).
- **Color schemes** — 5 modes (App theme, simple color, vibrant color, Material You, blur) with palette extraction from the cover.
- **Display options** — Small image, corner radius, player blur intensity, squiggly seek bar, scrolling text, remaining-time preference, album-artist name, album title, next song preview, extra metadata fields (bitrate, genre, year…) with draggable configuration; **Keep screen on** and **Touch only on thumb** live in the same section.
- **Buttons** — Circle play button, adaptive controls, animated controls, extra controls, button style (Normal/M3/Expressive).
- **Queue screen** - Compose UI with highlighted current song, repeat/shuffle, lock, drag reordering, locate-current-track, queue-local search, song actions and stop-after-song. When unlocked with an empty query, rows can be swiped right to remove with a Snackbar Undo; the overflow action remains available, and only one removal is pending until that Snackbar resolves. One active playback queue, plus persistent named queues that can be saved, renamed, deleted and switched with their own resume position and repeat/shuffle mode (ADR-041). Duplicate save/rename names offer Keep both (suffix), Replace existing or Rename. On Rename, Replace deletes the selected saved queue and renames the current queue to that name; if the deleted target was the active named queue, its marker is cleared; the active playback queue is untouched. Limits are 100 queues and 80 characters with an explicit error, unless the opt-in Auto-delete oldest saved queue preference is on: then saving the 101st queue deletes the least recently used saved queue (the active saved queue is protected) and reports the removed name. Saved queues offer Merge into…: the chosen target keeps its name, resume state and order, receives the source queue's songs appended, and can skip duplicate media ids; the source queue is kept and no new queue is created. The named-queue manager offers First/Previous/Next over one stable creation order (`createdAt ASC, id`), only when the current timeline exactly matches the active named snapshot (IDs/order/count), with no wrap and clear first/last/empty/unrelated-queue messages; direct row switching is unchanged. The queue overflow menu offers Reshuffle queue only while shuffle is on and the queue is non-empty and randomize is not active: it rebuilds a fresh shuffle order starting at the current item, keeps the current track/position, queue IDs/order, repeat, the active named-queue binding and the named snapshot's item list/order unchanged, and persists the new order through the standard save path (which may refresh the active named queue's resume metadata, per ADR-041/045); shuffle off is an explicit no-op with feedback and is never enabled implicitly, while randomize reports that it has no fixed order to rebuild. Queue multi-selection is keyed by `QueueSong.key`: long-press enters selection, tap toggles, Select all/Cancel are explicit, and at least two selected rows can be dragged as one block. Drops insert before the target when moving upward and after it when moving downward; a drop inside the selected range is a no-op. Selection/drag are disabled while searching or locked, while swipe and single-item drag remain outside selection. The service applies repeated timeline moves, remaps the current/stop positions, and saves the final full queue, including duplicate media IDs and shuffle/sequential modes. When a non-empty queue finishes, an end footer offers Replay (from the first item of the current effective/shuffled order) and Clear (explicit full clear, independent of the keep-current preference); the existing clear-on-completion preference and empty state remain unchanged (QueueFragment navigateUp is best-effort and does not close this Compose sheet). Queue filtering preserves original indices for playback/edit actions. Aurora hosts the same full screen; other appearances retain the dialog. A configurable **Queues** library category (hidden by default; enable it in Settings > Library) browses the current playing queue and all saved queues, marks the active saved queue with its song count, and offers save/rename/delete/switch actions. Opening the playing-queue row reuses the existing queue dialog; the category is excluded from the Aurora drawer, which already has a fixed Queue destination.

- **Lock screen player** (`Settings > Lock screen player`, disabled by default) — an opt-in full-screen Compose player shown over the system keyguard with `setShowWhenLocked` / `setTurnScreenOn`. It provides cover, title/artist/album, seek bar, shuffle/prev/play-pause/next/repeat, the playing queue (tap to jump) and lyrics (synced highlighting/seek-to-line or plain text) panels, a landscape cover/controls split, blurred-cover or user-picked wallpaper, and artist/folder/genre/Favorites shortcuts that open the matching library detail screen. Cover gestures reuse `PlayerGesturesController` (tap, double-tap edges/center, horizontal flings). An upward flick dismisses it. The screen-off trigger is a dynamic receiver registered by `PlaybackService` only while the active local or Cast player is playing or playWhenReady, so it costs nothing on an idle or paused queue. Options: skip when the device is unlocked (default on) and skip when paused for more than one minute (default on); "Preview lock screen player" bypasses both. A "Lock screen permissions" guide reuses the OEM detection from `PowerManagementGuide` and exposes overlay permission status, app notification settings, the battery guide and app details. When Ghost mode is enabled its top bar offers a ghost-search entry that delegates to the guarded GhostSearch destination.

## 8. Network & Integrations

- **Scrobbling** — Last.fm/Libre.fm (username+password, MD5-signed session) and ListenBrainz (token): scrobble and now-playing toggles, per-service login state.
- **Last.fm** — Artist/album info, biography/wiki display, error-code mapping.
- **Deezer** — Track/album/artist search used for covers and artist images (best-image selection).
- **MusicBrainz** — Recording search/details used by the tag editor; Cover Art Archive URLs.
- **Built-in updater** — GitHub releases (stable/prerelease), weekly/daily/manual search modes, experimental updates toggle, markdown changelog dialog, ABI/flavor-aware APK download.
- **Chromecast** — GitHub and Play Store flavors only: Cast button in the now-playing toolbar (legacy overflow and Aurora header/overflow), system device chooser, queue/position hand-off between local `ExoPlayer` and media3 `CastPlayer`, and an embedded LAN HTTP server (audio with range requests and cover artwork) that runs only while casting. Repeat, play/pause, seek, next/previous and favorite keep working from the notification and in-app controls; the `fdroid` flavor has a no-op implementation and no Google Cast dependency.
- **Screencast without mirroring** — the Now Playing screen (cover, title, artist, album, lyrics and progress) is rendered on an external HDMI, Miracast/wireless display or Chromecast-as-display window through `android.app.Presentation`. The phone screen is not mirrored and playback keeps running in the local `ExoPlayer` pipeline, so the equalizer, ReplayGain, crossfade and gapless chain stay active. The Now Playing menu opens a toggle/display picker with wireless-display discovery and a shortcut to the system display settings; the presentation closes automatically when the display disconnects.
- **Network features** — Master switch, Wi-Fi-only mode, online artist images/album covers, preferred image size, 10 MB HTTP cache with offline interceptor.
- **Cover cache boundary** — Album-artist covers use a flat `4_<SHA-256>.jpg` cache key with canonical parent containment; numeric song/album/artist/playlist/genre keys are unchanged. This is source-level boundary hardening for the raw album-artist filename, not a security PASS or a proven arbitrary read/write; a real escape needs a pre-existing `covers/4_<first-component>` directory the code never creates. Legacy raw-name entries cold-miss and are not migrated. The source is implemented but not built into the current `66CC` APK; no runtime PASS.

## 9. UI, Themes & System

- **Themes** — Light/dark/system toggle, Material You (Monet dynamic color with palette styles and system contrast), pure black theme, custom font (Google Sans Flex).
- **Accent color** (`Settings > Appearance > Accent color`) — Choose the accent from a preset palette or an HSV custom picker; the color overrides the theme-derived accent in Compose (`SsilencceTheme`) and in legacy views on devices with Material dynamic-color support. "Default" restores the theme-derived accent. Aurora Glass keeps its fixed white accent and disables the picker until it is turned off.
- **Show unimportant settings** (`Settings > Advanced`) — Hides a curated set of advanced preferences (and categories left empty) when turned off. Enabled by default.
- **Disable album art** (`Settings > Library > Advanced`) — Shows placeholders instead of decoding cover/artist/playlist/genre/year artwork anywhere, including the media notification.
- **Battery & background guide** (`Settings > Advanced > Battery & background`) — Detects the device OEM (Xiaomi/MIUI, Huawei/EMUI, Samsung, OPPO, Realme, Vivo, ASUS, generic Android) and shows tailored background-playback steps, the current battery-optimization status, a "pin in recents" tip, and buttons for the system battery-optimization, app-details and known OEM auto-start screens. On MIUI it adds the launcher-shortcut permission guide.
- **Aurora appearance** — Optional native black-and-white glass appearance with a layered white S ribbon (distinct rear/main halos, static veil, horizon and top glow, eight-stop dark overlay), six primary destinations, a scrim-dismissable library drawer grouped as Library / Discover / Sound & system with the app-mark header, configurable library screens and Compose home/player chrome (compact home action rows with per-row equal heights, always-visible home search with Settings in overflow). The upper horizontal category strip is not used; navigation lives in the drawer and primary navigation (ADR-037). The classic Queues category is excluded from the Aurora drawer and can never become an Aurora start or last-page resume destination; Aurora retains its fixed Queue destination. Enabled only for new empty preference stores; saved themes, fonts and all seven player styles remain retained (ADR-036).
- **Aurora motion** — User switch; ribbon updates stop off-screen, outside the resumed lifecycle, with disabled system animations and in battery saver, where the ribbon paints the reference's un-waved shape. The pinned header actions fade their title and adopt floating glass pills as the page scrolls, snapping to the end state instead of interpolating when system animations are disabled. Saved player colors return when Aurora is off.
- **Aurora compatibility controls** — Category hold-to-search on the primary navigation, compact Peek and expressive morph controls are retained; supporting screens use the shell's actual navigation clearance, and landscape controls respect cutouts.
- **Aurora player preferences** — Scrolling metadata and extra-info changes remain live; scrolling respects visibility, reduced motion and battery saver. Sound and EQ transport actions open the actual native controls.
- **Aurora lyrics legibility** — inactive lyrics use a higher `.92` alpha; the Player/background-effects lyrics plate is fixed black (`.72`) with explicit white foreground (full-screen Player mode included) so media-derived tints cannot darken text; legacy/default inactive alpha remains `.4`.
- **Aurora equalizer layout** — Output-device header, actual engine band-count/profile chips, accessible vertical sliders and Bands/Sound pages reuse existing profile/effect commands.
- **Capability-aware reference controls** — Tags/composers and QR sharing remain visibly unavailable, not simulated features. Crossfade, manual lyrics timing, mono output and song-count timer are implemented with real controls. Named queues and queue search are implemented and no longer listed as unavailable (ADR-041). See `docs/AURORA_REFERENCE.md`.
- **App language** — ~40 locale translations, per-app language override.
- **Library UI** — Configurable visible categories (max 5, draggable), tab titles mode, remember last page, appbar mode (compact/simple/collapsing), rotation lock.
- **Entity menu customization** — Appearance > Menu actions lets you show/hide and reorder the actions of the song, album, artist, genre, playlist and folder option menus. Defaults keep every action in its current order; hidden actions are removed from the inflated menu and the rest are re-inserted in the saved order while submenus and uncatalogued actions are preserved. Genre customization applies to the genre and year detail overflow menu because genre rows have no item popup of their own.
- **Widgets** - 3 Glance widgets (responsive, card, full) with cover, title, artist, progress and controls; per-widget System/AlbumArt/Wallpaper themes, 0-100% transparency with heuristic 0.35 surface/0.30 scrim alpha floors (not a guaranteed contrast ratio), a shared empty state that compacts below 160dp so the title/action stay visible, and a Compose configure/reconfigure activity; dynamic colors, widget layout style, third-line content, corner radius. Wallpaper themes use the public system wallpaper colors (API 27+) and fall back to album art or system colors on API 26 or when unavailable. The AA-10 V4 source is live-integrated and independently reviewed; it remains unbuilt and runtime-pending, with no AA-10 PASS.
- **Media notification** — Custom Media3 notification provider with a configurable compact (up to 3) and expanded (up to 5) arrangement of previous, next, play/pause, favorite, FF, RW, close, shuffle and repeat; a stateful favorite heart; a Close/Add-to-playlist slot with a replace option; an optional `Ghost search` button shown only while ghost mode is enabled and restricted to the app's own controller; and a lock-screen artwork toggle that omits artwork from session metadata. Defaults match the previous notification (previous/play-pause/next plus repeat/shuffle).
- **Notification styles** - System (Media3, default), Small, Big simple and Big with upcoming songs, rendered by a custom Media3 `MediaNotification.Provider` with RemoteViews. Big styles show artwork, title/artist, a progress bar with elapsed/total time and the configured compact/expanded buttons; the advanced style adds favorite and add-to-playlist actions plus the next three upcoming songs. Optional always-expanded mode uses the big layout while collapsed. Backgrounds can follow the app theme, the cover palette, or a custom color. The custom big content view keeps notifications expandable on Android 10 and earlier; Android 13 and later may replace custom media layouts with the system media controls.
- **Android Auto** - Hierarchical media browsing via media IDs and the Automotive app descriptor, with roots for songs, albums, artists, album artists, composers (API 30+), genres, playlists, folders (flat or hierarchical) and the current playback queue. Auto media button preferences expose fast forward/rewind, favorite, shuffle and repeat; seek buttons follow the configured interval and short-track threshold.
- **App shortcuts** — Four built-in static shortcuts (last added, top tracks, favorites, shuffle all) plus dynamic per-entity launcher shortcuts for albums, artists, folders and playlists; adding asks for confirmation and unavailable targets are reported (ADR-044).
- **System search** — `searchable.xml` integration.
- **Crash handler** — Error activity saving `.log` reports with copy/share/report/restart actions.
- **Backup/restore** - ZIP backups of settings, playlists (M3U), favorites, play counts, named queues, per-file resume positions, per-song speed and pitch, lyrics cache, song notes and custom artist images; restore is selective (a picker over all ten content types, nothing preselected), validates empty/non-backup/unrestorable archives with honest warnings, and lyrics/artist-image entries round-trip reliably (serializable lyrics cache, no premature ZIP closure, bounded streaming restore). Playlist write failures abort creation with a failure result; legitimate empty playlists are stored as valid `#EXTM3U` entries so their entities round-trip. Settings restore is a live typed SharedPreferences import: it validates the XML before mutation, rejects plain DOCTYPE/DTD and oversized/malformed entries without aborting later archive entries, replaces the cached whole map through the app's singleton, refreshes the Settings screen after a successful commit, and does not leave a stale cache that a later edit could write back. A mixed restore with one failed selected entry and another successful import reports an explicit partial result instead of full success; valid-only restores and zero-import outcomes keep their existing messages. Restored XML may be reserialized, so durability is semantic rather than byte-identical. Playlist restore keeps its separate non-interactive merge-into-existing policy: an exact-name existing playlist receives the backup's resolvable songs without a conflict dialog, suffix, Replace or Rename choice, and is not routed through the device-import conflict dialog. A successful manual backup also offers a Compose "Backup saved" sheet with a read-only share action: the just-written SAF archive is copied into a private cache slot and exposed through the existing FileProvider with MIME `application/zip`; Done/cancel leaves the backup intact, staging/URI/chooser failures show a clear error without failing the backup, and scheduled backups are never auto-shared. Opt-in scheduled backups write the same archive to a user-chosen SAF folder with battery/storage-aware WorkManager scheduling; daily, weekly and fixed "every 30 days" cadences are supported (ADR-043, ADR-047, ADR-048). Favorites use a dedicated `Favorites/` M3U entry and are excluded from the generic `Playlists/` set in new archives; archives that keep Favorites under `Playlists/` still restore them when Playlists is selected. Play counts (`statistics/play_counts.json`) merge by max play/skip/time values; named queues (`queues/named_queues.json`) preserve or replace ids, enforce the 100-queue cap and resolve name collisions; per-file positions (`positions/track_positions.json`) keep the newer `updated_at`. Empty JSON lists are valid no-ops, malformed selected JSON entries are recorded as per-entry failures while archive/entry size limits still abort, and restoring only Playlists from a new archive no longer implicitly restores Favorites. Song notes are stored under `notes/*.txt` and restored as their own content type with a 1 MiB per-entry limit. Per-song playback parameters are stored in `playback/song_playback_params.json` as an optional restore section; entries with invalid song ids or out-of-range speed/pitch values are ignored, and other sections are unaffected.

## 10. Metadata & Info

- **Tag editors** — Single-song editor plus retained legacy album/artist editors using TagLib/Jaudiotagger: full field editing, covers via Photo Picker, lyrics, MusicBrainz search dialog, batch save with MediaStoreWriter, album-artist/conductor fields. The album/artist single-entity menu actions route to the batch editor.
- **Multi-song batch tag editor** — The song multi-select menu and the single-entity album/artist tag actions open a Compose editor for the 17 text fields plus the cover. Fields show a common value, `Varies` or `Not set`; every field defaults to `Keep`, and only explicit `Set`/`Clear` fields are written. Values are aggregated from every readable selected file, unreadable/missing songs are reported as skipped, and writes reuse `MetadataWriter` with a read-back report for each file and field (`Written`, `Cleared`, `Unsupported`, `Mismatch`, `KeptChanged`). Per-file values are available from each field row, skipped files are listed before save, and the writing state can stop after the current file. The cover can be replaced with a Photo Picker image or removed from every selected file, with a read-back cover status and a MediaStore album-art refresh. Every file is copied to `cacheDir/tag-write-backup/` before the destructive open; a failed write restores the current file, and the result screen offers a session undo that restores every file written in the session. The runtime format matrix is still unproven and the operation remains sequential and foreground-only. The legacy album/artist editors aggregate all selected files, show `Varies`, write only changed fields, confirm destructive totals/disc writes, and no longer clear `ARTIST` conditionally; they stay in the manifest but are no longer reachable from menus because the single-entity album/artist actions now route to the batch editor.
- **Song info** — Bitrate, format, sample rate, channel mode, bit depth, container, codec and the decoder actually used (from Media3 `AnalyticsListener`, or the custom AIFF/DSD extractor description), a metadata completeness check with refresh, and an explicit unsupported-decoder explanation for APE/WMA.
- **Play statistics** — Plays/skips counts, last played date, top tracks per album/artist, and period-aware top songs/artists with percentages (ADR-040).
- **Web search** — Song web search dialog (Google, Last.fm, Wikipedia, YouTube) with localized URLs.

## 11. Utilities

- **Sleep timer** - AlarmManager-based countdown or exact HH:MM end time, stop after N songs (the current song counts as the first; only tracks that play to their end are counted), one-tap stop after this song, fade-out and finish-last-song (time modes), last five time-based choices as one-tap history chips with a clear action, and an optional "Stop only music if app UI is in foreground" policy that pauses only playback when the app is visible and also stops the media service when the timer ends in the background.
- **Audio cutter / trimmer** — Song, playlist-song, now-playing and multi-select menus open a Compose trimmer with a waveform-less start/end range slider, a ±1 s minimum selection, live time labels and clipped ExoPlayer preview playback. Export copies the selected range without re-encoding via `MediaExtractor` + `MediaMuxer` (M4A/MP4 AAC, ADTS AAC, and OGG Opus/Vorbis on Android 11+), while MP3 is copied frame-aligned with its ID3v2 tag preserved; other codecs show a clear unsupported state. The destination is chosen with the Storage Access Framework.
- **Set as ringtone / notification / alarm** — Built on the trimmer: the clip is published to the matching MediaStore audio collection (Android 10+) or the legacy `Ringtones`/`Notifications`/`Alarms` folder (Android 8–9) and set through `RingtoneManager`. `WRITE_SETTINGS` is requested through `ACTION_MANAGE_WRITE_SETTINGS`; the existing default sound is never deleted.
- **Sharing** — Share songs/albums via intents.
- **Storage** — Storage volume enumeration, SAF persisted permissions, folder chooser dialog.
- **OEM helpers** — Xiaomi Mi Play detection, MIUI/Samsung media output switcher.
- **Permission onboarding and first-run setup** — `PermissionsActivity` with guided permission requests (storage/audio, images, Bluetooth, exact alarms), followed by the `SetupWizardActivity` first-run library setup on new installations.

## Notes

- Flavor differences: the updater and Lyrically provider exist only in the `github` flavor; `fdroid` has no updater; `playstore` uses a stub for the Lyrically API. Chromecast is compiled only into `github` and `playstore`; `fdroid` is GMS-free and uses the no-op provider.
