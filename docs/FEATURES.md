# Feature Inventory

Complete inventory of user-facing features available in the ssilencce app (fork of Booming Music).

Related: `docs/CODE_MAP.md` (per-file code analysis).

## 1. Playback & Audio

- **Media3/ExoPlayer engine** — `PlaybackService` (MediaLibraryService) owns the player, MediaSession, equalizer, notifications, Bluetooth handling and widgets.
- **State persistence** — Queue, position and shuffle order are persisted in Room/SharedPreferences and restored on app start (`PersistentStorage`); queue rows are keyed by position (Room v8), preserving repeated songs. Pending queue edits are retained through pause, and an ordered application-owned writer flushes the final service snapshot without blocking Main. Named queues add snapshots with their own resume position (ADR-041, ADR-045). Switching named queues first awaits the outgoing snapshot (ADR-046); a persistence failure or an unstable departing timeline after bounded retries aborts the switch instead of silently losing the edits. Pending IO cannot be guaranteed after an immediate whole-process kill.
- **Playback modes** — Repeat, shuffle (normal), play on startup (never / last position / first song), clear queue on completion.
- **Per-track resume** — Optional opt-in remembers the last position of long-form tracks (10 minutes or more), resumes them later and clears the position on completion. Positions are written through the ordered non-blocking `TrackPositionWriter`; seek-generation guards prevent stale bookmark seeks after manual seeks (ADR-042).
- **Session recovery** — Optional opt-in resumes the saved queue and position after Android recreates the playback service; it does not claim to survive force-stop (ADR-042).
- **Quick Settings tile** — Playback tile mirrors playing/paused/unavailable state from the live session and toggles play/pause with a lifecycle-bounded controller (ADR-042).
- **Smart shuffle modes** (`ShuffleManager`) — Pure random, most played, favorites, forgotten songs, recently added, combined, by-group shuffle; album/artist plus album-artist/composer most-played strategies; album-artist works on all supported versions, while composer (Android 11/API 30+ only, matching the Composers category) is hidden below API 30; per-open shuffle behavior (on/off/remember). Special-shuffle replacement rebuilds the weighted queue and starts playback at the first item (position 0); it does not preserve the previous current item, position or play/pause intent. Non-special/native shuffle behavior is unchanged.
- **Queue behavior** — Configurable tap-on-song action (play single song / play whole list / play next / queue at end) and queue-clearing behavior (remove all vs. keep current).
- **Controls** — Rewind with back button, configurable seek interval (5–60 s), mini-player swipe-to-skip, extra controls, adaptive/circle/animated buttons.
- **Headset button mapping** — Playback → Headphones opens a Compose dialog for single, double, triple and long-press actions from a transport-only set (Play/Pause, Next, Previous, Seek forward, Seek backward, Nothing), an optional 4+ Seek forward action, and a 250–600 ms delay. Defaults preserve single Play/Pause, double Next, triple Previous, long Play/Pause, 4+ off and 300 ms. Dedicated Next/Previous/FF/Rewind keys remain with Media3. Long press and mapping depend on the headset/Android/AVRCP stack; the dialog documents the limitation.
- **Audio processing** (`renderer` + `processor`) — Per-channel balance, ReplayGain (album/track mode, preamp, peak limiting on 16/24-bit PCM) injected into `DefaultAudioSink`; ALAC hardware-decoder workaround for broken high-bitrate M4A.
- **Software decoding fallback** — Jellyfin FFmpeg decoder (`media3-ffmpeg-decoder`) auto-loaded by the Media3 extension renderer for codecs MediaCodec cannot handle (e.g. ALAC, and rare codecs inside containers Media3 demuxes); Media3 1.10.1 provides no demuxers for ASF/WMA, APE, DSF/DFF or AIFF, so those containers are not playable.
- **Audio device integration** (`AudioOutputObserver`) — Resume on headphone/Bluetooth connect, pause on disconnect, pause at zero volume, system media output switcher (incl. MIUI/Samsung OEM intents), Xiaomi Mi Play detection, bit-perfect state.
- **Audio focus** — Four modes: Normal, Ignore focus, Ask before taking focus (with confirmation when another app is audible) and Resume after call. Ask uses a restorable Compose dialog tied to the live request; repeated play preserves it, while explicit/no-op pause, cancel, mode change/abandon/release invalidate it. Stale confirmations cannot start playback. Transient loss and ducking remain owned by `AudioFocusController`; there is no automatic timeout (ADR-042, ADR-045).
- **Advanced** — MP3 index seeking, stop when closed from recents, play option always visible / whole list, play all songs when searching.

## 2. Equalizer & Sound

- **Equalizer** with two engines: classic `android.media.audiofx.Equalizer` and `DynamicsProcessing` (API 28+, multiband compressor/limiter); band counts/configuration follow the selected engine's capabilities.
- **Effects** — Bass boost, virtualizer, loudness, compressor, limiter.
- **Balance, tempo (speed/pitch), system volume** controls.
- **EQ profiles** - Named profiles with broad output-type associations and optional exact per-device keys (hashed Bluetooth/USB identity where the OS exposes it); exact device wins over type, unassociated outputs keep the current profile. Profile saver/editor exposes “Use with this device” when an identity is available. Import/export (JSON and AutoEq TXT format), persistence in DataStore.
- **ReplayGain** - Album/track/off modes with preamp, reading standard, iTunes `----:com.apple.iTunes:` and Opus R128 tags with Standard > iTunes > R128 alias priority; malformed/blank gains and peaks are treated as missing. A **Calculate ReplayGain** action in the song-selection, album and artist menus measures audio with EBU R128/BS.1770 (400 ms blocks, 100 ms hop, gating), writes format-aware tags, verifies them by reading back, and writes album gain only when the complete album is selected. A measured 0.00 dB tag remains present and uses the with-tag preamp. A complete-album write failure suppresses and rolls back new album gain/peak for the whole album; remaining tracks may still receive track tags. Cancellation preserves completed/failed counts, and playback peak limiting applies to any finite positive peak, including tags above 1.0. The writer reopens the file to verify persisted tags, writes WAV through an explicit RIFF `ID3 ` chunk codec (preserving `fmt `/`data` and non-RG tags) with a staged app-private persistent backup/restore under `noBackupFilesDir/replaygain-wav-backup` on failure, and M4A as `----:com.apple.iTunes:REPLAYGAIN_*` freeform atoms, and fails closed only if the container still cannot persist the values; corrupt or materially truncated decodes (including AAC encoder-delay-aware duration checks) fail per file, and the result lists each failed title/reason. WAV recovery copies are app-private, survive process death/reboot, and are excluded from cloud/device-transfer backups; recovery is per-song on the next write, with no global startup scan, so stale backups for songs never rewritten can persist. Legacy cacheDir backups are not migrated or swept. The current AA-06 codec/writer checkpoint is not yet independently accepted; final review, frozen build and device WAV/M4A gates remain pending.
- **Sound settings sheet** — Balance, tempo and volume controls reachable from the player; ReplayGain mode/preamp and the calculation action live in the Equalizer screen.

## 3. Lyrics

- **Synced and plain lyrics** — LRC/enhanced-LRC and TTML (Apple Music) parsing with translations, transliterations and actor assignment (duets M/F).
- **Sources** — Embedded tags, lyrics files (`.lrc`/`.ttml`), embedded via LRC files, and online providers: **Lyrically** (iTunes-based, Jaro-Winkler scoring), **BetterLyrics**, **LRCLib** (close-duration search); cached in Room (`LyricsEntity`).
- **Syllable mode & karaoke** — Word-by-word highlighting (`SpannedWordText`), karaoke-style text fill, progressive coloring, blur/shadow text effects, animated backgrounds.
- **Lyrics display** — Full-screen lyrics view and lyrics over the cover, auto-scroll, active line centering, horizontal centering, RTL support, custom font import, line spacing, font sizes and bold per mode (synced/plain × player/fullscreen).
- **Lyrics editor** — Edit text with preview, instrumental detection, online search, save to lyrics/LRC files.
- **Instrumental detection** — By title keywords (configurable identifiers) or short exact lyrics.
- **Advanced** — Ignore blank lines, preferred file format (TTML/LRC), force UTF-8, resume-on-seek, line-crossfade settings.

## 4. Library & Organization

- **Media collections** — Songs, albums, artists, separate album artists and composers, genres, release years, folders (filesystem explorer with SAF), playlists.
- **Composer and album-artist tabs** — Album artists reuses the existing album-artist queries and detail/playback flow. Composers uses `MediaStore.MediaColumns.COMPOSER` on Android 11+ (the category is hidden below API 30; no metadata scan) and reuses the artist detail/playback screens. When both Artists and Album artists are visible, Artists lists regular artists and hides the legacy “Only album artists” toggle; when Album artists is hidden, the previous behavior is unchanged.
- **Album composer filter** — On Android 11+ the album list offers Filter by composer when album songs contain composer tags. A Compose choice dialog lists All composers plus normalized composer names and filters the existing album grid; the action is hidden below API 30 and when no composer data exists. The selection is restored after recreation.
- **Genre subcategories** — Genre detail offers View with Songs, Albums and Artists. Albums and artists reuse the existing album/artist adapters and detail screens and are derived from the same genre song query. Sort menus, Play, Shuffle and quick search follow the visible subcategory, while the header keeps the full genre song count and duration; the selected subcategory is restored after recreation.
- **Home screen** — Greeting header, last added, top tracks, history, shuffle button and suggestions.
- **Content types** — Favorites, history (configurable cutoff interval, individual and multi-select removal), last added (configurable interval), not-recently-played, top tracks, top albums/artists, never played.
- **Not Recently Played threshold** — The smart list defaults to the history interval and offers a Compose dialog to set an arbitrary 1–3650-day window or return to the history interval. The choice is persisted in existing preferences, applies to the Home suggestion and updates the list and subtitle after saving.
- **Play counts** — Per-song play/skip counters and time played (incremented at 50 % of duration), top-100 flows.
- **Non-destructive statistics reads** — Play-count and history reads filter missing/deleted files without deleting rows; explicit `Repository.deleteSong`/`deleteSongs`, `clearPlayCount` and `clearSongHistory` remain the only cleanup paths. The 100-row `PLAY_STATS_LIMIT`/`HISTORY_LIMIT` is still applied before the missing-file filter, so sparse windows can show fewer than 100 and omit valid rows beyond the window; permanent missing-row cleanup is explicit only. Source is implemented but not built into the current `66CC` APK; no feature closure or runtime PASS.
- **Play statistics periods** — Top Tracks and Top Artists support this week, this month, last 12 months, this year and all time. Period artist attribution uses recorded event names; later metadata changes do not rewrite it. Artist percentages use all plays in the selected period, not just the displayed top 100, and denominator-only changes remain reactive. Snapshot-only artists remain visible with unavailable media actions disabled. All time retains earlier aggregate counts and artist-ID identity (ADR-040). The options menu exports the current period's top 100 Top Tracks or Top Artists as UTF-8 CSV through SAF, with RFC 4180 escaping and formula-injection neutralization; no storage permission is required. An optional automatic export can write the latest completed local calendar week, month or year to a persisted SAF folder through a daily WorkManager check: up to two top-100 CSVs use the same writer and auto names, each file is staged as `.partial` and renamed only after the complete write, only the latest completed period is caught up after missed runs, NoData creates no files, handled failures retry the pending period on the next daily check, and older files are never deleted.
- **Sorting** — Locale-aware numeric collator (natural number order), article-ignoring sort (The/A/El…) with a user-editable keyword list, per-entity sort keys with persistence, and filename, path, track-number and date-modified keys on the song and file lists.
- **List display** — Song rows can follow the sort order (File name key shows the file name), always show the song title, or always show the file name. An optional, default-off switch appends a localized date-only modification label to the existing secondary text. Global-search song results use the same title mode and suffix. Compact album/artist rows and Home suggestions have no secondary text view and remain unchanged. Both controls live in Appearance > Display and apply on the next list bind or reload.
- **Views** — List/grid modes, 5 grid view types (normal, card, colored card, circle, image), configurable grid size, larger header image, fast scroller.
- **Library filtering** - Whitelist/blacklist folders (`InclExclDao`), minimum and maximum song duration (maximum 0 = unlimited; library queries only), minimum songs per artist/album. Duration bounds are library-browsing only: queue resolution, the unknown-genre list, ID/path/file-provider resolution, delete cleanup, saved playlists and favorites are not duration-filtered.
- **Covers** — Embedded/folder art (cover.jpg etc.), MediaStore art, ignore-MediaStore-covers option, use-folder-art option, online artist images and album covers (Deezer), preferred image size.
- **File operations** — Batch delete with MediaStore trash requests (recoverable) and SAF fallback, delete to trash option.

## 5. Playlists

- **CRUD** — Create, rename, edit (name, description, custom cover via Photo Picker), delete playlists; favorites playlist.
- **Playlist management** — Drag & drop reordering, internal search, song counts, multi-select.
- **Import/export** — Import device playlists (M3U and others), export as `.m3u`, `.m3u8` or `.pls` (MediaStore on Android 10+). Device import uses only the checked songs (deduplicated by ID); no exact name collision imports directly. An exact collision opens a Compose dialog with Keep both (default, first free suffix 1..100), Replace existing (single exact non-Favorites target only, transactional contents replacement preserving playlist ID/name/description/cover) and Rename imported (validated new name, existing playlist untouched). Cancel never mutates. Creates and replacements run in Room transactions and name resolution is serialized; success reports the actual stored name. Single and batch export share a format chooser. Directory writes stage beside the target. On Q+, exports use `MediaStore.Files` with the format's concrete playlist MIME (not the legacy `Audio.Playlists` name-rewriting path); the writer stages and publishes complete content before a checked rename replaces the same-name target. Pre-commit failure preserves old bytes and attempts to restore its name. A provider refusing rollback can leave old bytes under a backup name; failed post-commit cleanup can leave an extra backup. The format chooser is a Compose dialog that survives recreation; selecting an export dismisses the dialog and hands the request to a process-owned executor, so rotation does not cancel it and a restored token cannot start it twice. Public MediaStore APIs provide no atomic-swap or power-loss guarantee (ADR-044).
- **Add-to-playlist** — Compose bottom sheet with search and multi-select.

## 6. Search

- **Global search** — Text field, voice input, 300 ms debounce, grouped results (albums, artists, songs, playlists, genres).
- **Search filters** — Smart, basic and last-added filters; scoped searches within genre, playlist, year and folder.
- **Settings search** — A search action in Settings indexes every preference section, groups matches by section and opens the selected section (scrolling to the key when present).
- **Quick list search** - A bottom search field on the songs, albums, artists, playlists, genres, years and folders lists filters the loaded list in place and restores it when cleared. The query is fragment-owned, saved across configuration recreation and replayed against the list so the visible text and rows remain aligned. The same bar is available on the generic detail/statistics list and on the song sections of album, artist, genre, year, folder and playlist detail; album/artist filtering is songs-only, folder matching includes the file name, and playlist filtering is drag-safe (filtered rows are never persisted and the full order is saved on pause).
- **System integration** — Android searchable config, search action, hold-tab-to-search.

## 7. Now Playing Screen

- **7 player styles** — Default, FullCover, Gradient, Plain, Material 3, Expressive, Peek — retained View/controls fragments outside Aurora; Compose Aurora chrome reuses their shared cover pager and actions without adding a style. The Aurora square cover sits centered in its stage (360 dp, 280 dp compact) with a smooth pre-blurred cached bitmap halo (bounded cache, single draw per frame, no per-frame blur), and FullCover keeps its glass controls over the reference backdrop.
- **Gestures** — Configurable single-tap, double-tap (left/right/center), long-press on cover; swipe on cover, swipe anywhere, swipe-up for queue, swipe-down to dismiss.
- **Page transitions** — Carousel effect plus 10 PageTransformers (depth, 3D flips, hinge, cascading, parallax, vertical stack, zoom-out…).
- **Color schemes** — 5 modes (App theme, simple color, vibrant color, Material You, blur) with palette extraction from the cover.
- **Display options** — Small image, corner radius, player blur intensity, squiggly seek bar, scrolling text, remaining-time preference, album-artist name, album title, next song preview, extra metadata fields (bitrate, genre, year…) with draggable configuration.
- **Buttons** — Circle play button, adaptive controls, animated controls, extra controls, button style (Normal/M3/Expressive).
- **Queue screen** - Compose UI with highlighted current song, repeat/shuffle, lock, drag reordering, locate-current-track, queue-local search, song actions and stop-after-song. When unlocked with an empty query, rows can be swiped right to remove with a Snackbar Undo; the overflow action remains available, and only one removal is pending until that Snackbar resolves. One active playback queue, plus persistent named queues that can be saved, renamed, deleted and switched with their own resume position and repeat/shuffle mode (ADR-041). Duplicate save/rename names offer Keep both (suffix), Replace existing or Rename. On Rename, Replace deletes the selected saved queue and renames the current queue to that name; if the deleted target was the active named queue, its marker is cleared; the active playback queue is untouched. Limits are 100 queues and 80 characters with an explicit error rather than auto-delete. The named-queue manager offers First/Previous/Next over one stable creation order (`createdAt ASC, id`), only when the current timeline exactly matches the active named snapshot (IDs/order/count), with no wrap and clear first/last/empty/unrelated-queue messages; direct row switching is unchanged. The queue overflow menu offers Reshuffle queue only while shuffle is on and the queue is non-empty: it rebuilds a fresh shuffle order starting at the current item, keeps the current track/position, queue IDs/order, repeat, the active named-queue binding and the named snapshot's item list/order unchanged, and persists the new order through the standard save path (which may refresh the active named queue's resume metadata, per ADR-041/045); shuffle off is an explicit no-op with feedback and is never enabled implicitly. Queue multi-selection is keyed by `QueueSong.key`: long-press enters selection, tap toggles, Select all/Cancel are explicit, and at least two selected rows can be dragged as one block. Drops insert before the target when moving upward and after it when moving downward; a drop inside the selected range is a no-op. Selection/drag are disabled while searching or locked, while swipe and single-item drag remain outside selection. The service applies repeated timeline moves, remaps the current/stop positions, and saves the final full queue, including duplicate media IDs and shuffle/sequential modes. When a non-empty queue finishes, an end footer offers Replay (from the first item of the current effective/shuffled order) and Clear (explicit full clear, independent of the keep-current preference); the existing clear-on-completion preference and empty state remain unchanged (QueueFragment navigateUp is best-effort and does not close this Compose sheet). Queue filtering preserves original indices for playback/edit actions. Aurora hosts the same full screen; other appearances retain the dialog. A configurable **Queues** library category (hidden by default; enable it in Settings > Library) browses the current playing queue and all saved queues, marks the active saved queue with its song count, and offers save/rename/delete/switch actions. Opening the playing-queue row reuses the existing queue dialog; the category is excluded from the Aurora drawer, which already has a fixed Queue destination.

## 8. Network & Integrations

- **Scrobbling** — Last.fm/Libre.fm (username+password, MD5-signed session) and ListenBrainz (token): scrobble and now-playing toggles, per-service login state.
- **Last.fm** — Artist/album info, biography/wiki display, error-code mapping.
- **Deezer** — Track/album/artist search used for covers and artist images (best-image selection).
- **MusicBrainz** — Recording search/details used by the tag editor; Cover Art Archive URLs.
- **Built-in updater** — GitHub releases (stable/prerelease), weekly/daily/manual search modes, experimental updates toggle, markdown changelog dialog, ABI/flavor-aware APK download.
- **Network features** — Master switch, Wi-Fi-only mode, online artist images/album covers, preferred image size, 10 MB HTTP cache with offline interceptor.
- **Cover cache boundary** — Album-artist covers use a flat `4_<SHA-256>.jpg` cache key with canonical parent containment; numeric song/album/artist/playlist/genre keys are unchanged. This is source-level boundary hardening for the raw album-artist filename, not a security PASS or a proven arbitrary read/write; a real escape needs a pre-existing `covers/4_<first-component>` directory the code never creates. Legacy raw-name entries cold-miss and are not migrated. The source is implemented but not built into the current `66CC` APK; no runtime PASS.

## 9. UI, Themes & System

- **Themes** — Light/dark/system toggle, Material You (Monet dynamic color with palette styles and system contrast), pure black theme, custom font (Google Sans Flex).
- **Aurora appearance** — Optional native black-and-white glass appearance with a layered white S ribbon (distinct rear/main halos, static veil, horizon and top glow, eight-stop dark overlay), six primary destinations, a scrim-dismissable library drawer grouped as Library / Discover / Sound & system with the app-mark header, configurable library screens and Compose home/player chrome (compact home action rows with per-row equal heights, always-visible home search with Settings in overflow). The upper horizontal category strip is not used; navigation lives in the drawer and primary navigation (ADR-037). The classic Queues category is excluded from the Aurora drawer and can never become an Aurora start or last-page resume destination; Aurora retains its fixed Queue destination. Enabled only for new empty preference stores; saved themes, fonts and all seven player styles remain retained (ADR-036).
- **Aurora motion** — User switch; ribbon updates stop off-screen, outside the resumed lifecycle, with disabled system animations and in battery saver, where the ribbon paints the reference's un-waved shape. The pinned header actions fade their title and adopt floating glass pills as the page scrolls, snapping to the end state instead of interpolating when system animations are disabled. Saved player colors return when Aurora is off.
- **Aurora compatibility controls** — Category hold-to-search on the primary navigation, compact Peek and expressive morph controls are retained; supporting screens use the shell's actual navigation clearance, and landscape controls respect cutouts.
- **Aurora player preferences** — Scrolling metadata and extra-info changes remain live; scrolling respects visibility, reduced motion and battery saver. Sound and EQ transport actions open the actual native controls.
- **Aurora lyrics legibility** — inactive lyrics use a higher `.92` alpha; the Player/background-effects lyrics plate is fixed black (`.72`) with explicit white foreground (full-screen Player mode included) so media-derived tints cannot darken text; legacy/default inactive alpha remains `.4`.
- **Aurora equalizer layout** — Output-device header, actual engine band-count/profile chips, accessible vertical sliders and Bands/Sound pages reuse existing profile/effect commands.
- **Capability-aware reference controls** — Tags/composers, manual lyrics timing, QR sharing, crossfade, mono and song-count timer remain visibly unavailable, not simulated features. Named queues and queue search are implemented and no longer listed as unavailable (ADR-041). See `docs/AURORA_REFERENCE.md`.
- **App language** — ~40 locale translations, per-app language override.
- **Library UI** — Configurable visible categories (max 5, draggable), tab titles mode, remember last page, appbar mode (compact/simple/collapsing), rotation lock.
- **Widgets** - 3 Glance widgets (responsive, card, full) with cover, title, artist, progress and controls; per-widget System/AlbumArt/Wallpaper themes, 0-100% transparency with heuristic 0.35 surface/0.30 scrim alpha floors (not a guaranteed contrast ratio), a shared empty state that compacts below 160dp so the title/action stay visible, and a Compose configure/reconfigure activity; dynamic colors, widget layout style, third-line content, corner radius. Wallpaper themes use the public system wallpaper colors (API 27+) and fall back to album art or system colors on API 26 or when unavailable. The AA-10 V4 source is live-integrated and independently reviewed; it remains unbuilt and runtime-pending, with no AA-10 PASS.
- **Android Auto** — Hierarchical media browsing via media IDs and Automotive app descriptor.
- **App shortcuts** — Four built-in static shortcuts (last added, top tracks, favorites, shuffle all) plus dynamic per-entity launcher shortcuts for albums, artists, folders and playlists; adding asks for confirmation and unavailable targets are reported (ADR-044).
- **System search** — `searchable.xml` integration.
- **Crash handler** — Error activity saving `.log` reports with copy/share/report/restart actions.
- **Backup/restore** - ZIP backups of settings, playlists (M3U), favorites, play counts, named queues, per-file resume positions, lyrics cache and custom artist images; restore is selective (a picker over all eight content types, nothing preselected), validates empty/non-backup/unrestorable archives with honest warnings, and lyrics/artist-image entries round-trip reliably (serializable lyrics cache, no premature ZIP closure, bounded streaming restore). Playlist write failures abort creation with a failure result; legitimate empty playlists are stored as valid `#EXTM3U` entries so their entities round-trip. Settings restore is a live typed SharedPreferences import: it validates the XML before mutation, rejects plain DOCTYPE/DTD and oversized/malformed entries without aborting later archive entries, replaces the cached whole map through the app's singleton, refreshes the Settings screen after a successful commit, and does not leave a stale cache that a later edit could write back. A mixed restore with one failed selected entry and another successful import reports an explicit partial result instead of full success; valid-only restores and zero-import outcomes keep their existing messages. Restored XML may be reserialized, so durability is semantic rather than byte-identical. Playlist restore keeps its separate non-interactive merge-into-existing policy: an exact-name existing playlist receives the backup's resolvable songs without a conflict dialog, suffix, Replace or Rename choice, and is not routed through the device-import conflict dialog. A successful manual backup also offers a Compose "Backup saved" sheet with a read-only share action: the just-written SAF archive is copied into a private cache slot and exposed through the existing FileProvider with MIME `application/zip`; Done/cancel leaves the backup intact, staging/URI/chooser failures show a clear error without failing the backup, and scheduled backups are never auto-shared. Opt-in scheduled backups write the same archive to a user-chosen SAF folder with battery/storage-aware WorkManager scheduling; daily, weekly and fixed "every 30 days" cadences are supported (ADR-043, ADR-047, ADR-048). Favorites use a dedicated `Favorites/` M3U entry and are excluded from the generic `Playlists/` set in new archives; archives that keep Favorites under `Playlists/` still restore them when Playlists is selected. Play counts (`statistics/play_counts.json`) merge by max play/skip/time values; named queues (`queues/named_queues.json`) preserve or replace ids, enforce the 100-queue cap and resolve name collisions; per-file positions (`positions/track_positions.json`) keep the newer `updated_at`. Empty JSON lists are valid no-ops, malformed selected JSON entries are recorded as per-entry failures while archive/entry size limits still abort, and restoring only Playlists from a new archive no longer implicitly restores Favorites.

## 10. Metadata & Info

- **Tag editors** — Song, album and artist editors using TagLib/Jaudiotagger: full field editing, covers via Photo Picker, lyrics, MusicBrainz search dialog, batch save with MediaStoreWriter, album-artist/conductor fields.
- **Multi-song batch tag editor** — The song multi-select menu opens a Compose editor for the 17 text fields. Fields show a common value, `Varies` or `Not set`; every field defaults to `Keep`, and only explicit `Set`/`Clear` fields are written. Values are aggregated from every readable selected file, unreadable/missing songs are reported as skipped, and writes reuse `MetadataWriter` with a read-back report for each file and field (`Written`, `Cleared`, `Unsupported`, `Mismatch`, `KeptChanged`). Per-file values are available from each field row, skipped files are listed before save, and the writing state can stop after the current file. Batch cover editing, session undo/rollback and in-place write backup/restore remain missing; the runtime format matrix is still unproven. The reviewed v2 source is live-integrated; no app build or runtime PASS is claimed. The legacy album/artist editors now aggregate all selected files, show `Varies`, write only changed fields, confirm destructive totals/disc writes, and no longer clear `ARTIST` conditionally; they remain separate legacy editors rather than being routed to the batch editor.
- **Song info** — Bitrate, format, sample rate, channel mode, metadata completeness check with refresh.
- **Play statistics** — Plays/skips counts, last played date, top tracks per album/artist, and period-aware top songs/artists with percentages (ADR-040).
- **Web search** — Song web search dialog (Google, Last.fm, Wikipedia, YouTube) with localized URLs.

## 11. Utilities

- **Sleep timer** — AlarmManager-based, countdown or exact HH:MM end time, fade-out, quit-after-end option.
- **Sharing** — Share songs/albums via intents.
- **Storage** — Storage volume enumeration, SAF persisted permissions, folder chooser dialog.
- **OEM helpers** — Xiaomi Mi Play detection, MIUI/Samsung media output switcher.
- **Permission onboarding** — `PermissionsActivity` with guided permission requests (storage/audio, images, Bluetooth, exact alarms).

## Notes

- Flavor differences: the updater and Lyrically provider exist only in the `github` flavor; `fdroid` has no updater; `playstore` uses a stub for the Lyrically API.
- Feature availability checks (`NetworkFeature`) gate images, lyrics APIs, scrobbling and the updater per build flavor.
