# ADR-025: Hierarchical Cover Art Resolution with Coil

## Status

Accepted

## Context

Covers come from multiple sources of different quality: embedded tags, folder art files
(`cover.jpg`, `folder.png`, ...), MediaStore album art, and online lookups (Deezer). Some
entities (genres, years, playlists) have no artwork at all and need generated mosaics.
External consumers (widgets, Android Auto, notification) need stable `content://` URIs instead
of file paths or network URLs.

## Decision

- Standardize image loading on Coil 3 (`coil`, `coil-compose`, `coil-network-ktor3`) with a
  custom `ImageLoader` registered in `App` and custom components:
  - `AudioCoverFetcher` (song/album): embedded TagLib front cover or folder art
    (`AudioCoverUtils`, 9 probe filenames, preference-gated) → MediaStore album art → Deezer
    (`deezerAlbum`/`deezerTrack`, network-feature gated, artist known).
  - `ArtistImageFetcher`: custom artist image file → Deezer artist search (paged, max 20) →
    MediaStore artist art.
  - `AutoGeneratedImageFetcher`: mosaics for genres/years from up to 9 distinct album covers
    (`AutoGeneratedImageUtil`/`MergedImageUtils`, 1600 px collage, rotated 9°).
  - `PlaylistImageFetcher`: custom playlist cover → auto-generated mosaic.
- Map domain entities to request models via `MapperStore` and produce deterministic cache keys
  via `KeyerStore` (artist key includes the custom-image signature; playlist key includes the
  song count).
- Match Deezer results with Jaro-Winkler title similarity (0.90 threshold) and pick image
  size per request.
- Serve stable cover URIs through `CoverProvider`, a `ContentProvider`
  (`content://<package>.cover`) that renders/JPEG-caches covers (1024 px, 7-day expiry,
  fallback JPEG) for MediaItems, widgets and Android Auto.
- Manage user-chosen artwork with `CustomArtistImageManager` (2048 px JPEG + MediaStore
  Artists notify) and `CustomPlaylistImageManager` (1080 px JPG in filesDir).
- Bridge to Media3 notifications via `CoilBitmapLoader` (1024 px cap, memory cache disabled)
  wrapped in `CacheBitmapLoader` (ADR-011).

## Consequences

- One loading pipeline with graceful degradation: offline or missing art always has a
  deterministic fallback chain ending in generated or placeholder art.
- Mosaics give genres/years/playlists real artwork without external data.
- Deterministic keyers make the disk/memory caches effective across list, detail, widget and
  notification requests.
- Deezer dependence is bounded (feature-gated, cached 4 days via OkHttp, ADR-020) and only
  kicks in when local sources fail.
