# AA-05 dated contract decision — 2026-11-10

**Authority:** USER DECISION 2026-11-10.
**Scope:** AA-05 advance shuffle (Most played album artists / Most played composers) and the
special-shuffle queue replacement contract.
**Status:** Decision recorded; source cleanup and OpenSpec amendment complete at source level.
No build, device or runtime PASS is claimed by this record.

## Decision

The **original weighted-shuffle contract** is authoritative:

1. Build the new weighted queue.
2. Install it from its first item at position 0.
3. Start playback.

Current-song, playback-position and paused/playing-intent preservation is **rejected**. A paused
player also starts the new weighted queue at position 0 and plays. The non-special `openShuffle()`
path is unchanged.

## Source delta in this decision

Removed from `PlayerViewModel.openSpecialShuffle()`:

- capture of `currentMediaItem`, `currentPosition`, `playWhenReady`, shuffle state and mapped index;
- shuffle-disable and indexed `setMediaItems(mediaItems, index, position)` / 0/0 fallback;
- `SET_UNSHUFFLED_ORDER` count/index/first-id extras and the 5-second `withTimeoutOrNull` wait;
- post-order media-id re-resolution, `seekTo(restoredIndex, currentPosition)` / `seekTo(0, 0L)`;
- `playWhenReady = wasPlaying` restoration;
- `AA05Shuffle` DEBUG diagnostics, `BuildConfig` import and `AA05_TAG`.

Restored: `shuffleModeEnabled = true`, plain `SET_UNSHUFFLED_ORDER`, then
`setMediaItems(mediaItems, true)`, `prepare()`, `play()`.

Removed from `PlaybackService`:

- `pendingUnshuffledOrderCount` / `pendingUnshuffledOrderFuture`;
- `applyPendingUnshuffledOrder()`;
- pending-order checks in `onSetMediaItems()`, including the preservation-only
  `player.shuffleModeEnabled` guard;
- pending-order branch in `SET_UNSHUFFLED_ORDER`;
- pending-order application in `onTimelineChanged()`;
- `AA05Shuffle` DEBUG diagnostics, `BuildConfig` import and `AA05_TAG`.

The plain `SET_UNSHUFFLED_ORDER` handler (`hasSetUnshuffledOrder`, `UnshuffledShuffleOrder`,
immediate success) is restored. The non-behavioral `val resolved` wrapper introduced by 4DA is
retained; it contains no preservation logic.

Removed from `Playback.kt`:

- `EXTRA_MEDIA_ITEM_COUNT`, `EXTRA_START_INDEX`, `EXTRA_FIRST_MEDIA_ID`.

`ShuffleManager.kt` is unchanged by this decision: the weighted album-artist/composer branches,
`ShuffleGroupKeyPolicy` grouping and `ShuffleModeAvailabilityPolicy` gate are retained.
